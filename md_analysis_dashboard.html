📈 Compute analysis from trajectory (in-browser)

Computes RMSD (Kabsch-aligned), radius of gyration, RMSF and an averaged contact map directly from the loaded trajectory — works for AMBER (.prmtop + .nc), GROMACS (.gro/.pdb + .xtc/.trr) and NAMD/CHARMM (.psf + .dcd); NGL normalises all coordinates to Å. The results open in their tabs with the usual plotting/export options. PBC note: if your solute crosses the periodic box edge, image it first — AMBER: cpptraj autoimage, GROMACS: gmx trjconv -pbc mol -center.

How to prepare your trajectory and generate every file this dashboard reads. Commands use <placeholders> — replace each with your system (e.g. <protein> → :1-596, <ligand> → :597). AMBER (cpptraj) lines match a typical ff19SB/TIP3P setup; GROMACS lines are the general equivalents.

⚠ First — fix periodic boundaries (imaging)

MD runs in a periodic box, so the solute can drift across an edge or split between images. Re-image before any analysis — otherwise RMSD, distances and contacts are wrong. Centre and wrap the solute, then (optionally) strip solvent to shrink the file.

AMBER · cpptraj
parm <topology>.prmtop
trajin <trajectory>.nc
autoimage                       # re-centre + wrap the solute into the box
strip :WAT,Na+,Cl-,K+           # drop water + buffer ions (keep structural metals)
trajout <trajectory>_imaged.nc
run
GROMACS
gmx trjconv -s <topology>.tpr -f <trajectory>.xtc -pbc mol -center -o <trajectory>_imaged.xtc

Load the imaged trajectory here. Aligning (fitting) on the protein is also recommended — cpptraj's rms first … does it; in GROMACS add a second gmx trjconv -fit rot+trans.

Two ways to feed the dashboard

A — Compute in the browser: load a topology (.prmtop / .psf / .gro) + trajectory (.nc / .dcd / .xtc / .trr) in the Interactions / 3D viewer, then use the “Compute analysis from trajectory” buttons — RMSD, RMSF, Rg, contact map and 🔗 interaction occupancy. Nothing is uploaded; everything is client-side.

B — Plot pre-computed files: generate them with cpptraj / gmx (commands below, and under each tab's “ⓘ How to generate this file”) and drop them in the matching tab.

The time axis (ns per frame)

cpptraj .dat files are indexed by frame number, not time. To put the x-axis in ns, the RMSD / Distance / H-bond tabs offer the 📄 from .in/.mdp button (reads the time step from your MD input), reading the time straight from an AMBER NetCDF, or typing ns/frame by hand: 

ns per frame  =  dt(ps) × ntwx ÷ 1000          # AMBER   (e.g. 0.002 × 5000 ÷ 1000 = 0.01 ns)
              =  dt(ps) × nstxout ÷ 1000        # GROMACS
              =  timestep(fs) × dcdfreq ÷ 1e6   # NAMD
